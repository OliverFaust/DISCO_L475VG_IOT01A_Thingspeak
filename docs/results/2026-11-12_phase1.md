# Phase 1 results (2026-11-12): Sensors + Console on the board

Phase 1 of the port: STM32CubeMX project, CSP4CMSIS 3.1.0, two processes (Sensors, Console), console
output every 5 s. No Wi-Fi yet. How the project was set up: `docs/08-how-it-was-made.md`.

## Set-up

| | |
|---|---|
| Board | B-L475E-IOT01A (ST-LINK/V2-1, firmware V2J46M31) |
| Host | Ubuntu 25.04 |
| Tools | STM32CubeMX 6.17.0, STM32Cube FW_L4 V1.18.2, STM32CubeIDE 2.1.0 (GNU Tools for STM32 14.3.rel1), STM32CubeProgrammer 2.22.0 |
| Library | CSP4CMSIS 3.1.0 (`lib/csp4cmsis/VERSION`) |

## 1. Code generation

`DISCO_L475VG_IOT01A_Thingspeak.ioc` loaded and generated with STM32CubeMX in command-line mode
(`STM32CubeMX -q script`, script: `config load <ioc>`, `project generate`, `exit`). Result `OK`.
A final regeneration after all `.cproject` edits left `.cproject` unchanged except for the order of
the source folders, and kept `Drivers/BSP/` and all `USER CODE` sections.

## 2. Build (headless)

```bash
~/st/stm32cubeide_2.1.0/headless-build.sh -data <empty workspace> -import "$PWD" \
    -cleanBuild DISCO_L475VG_IOT01A_Thingspeak/Debug
~/st/stm32cubeide_2.1.0/headless-build.sh -data <same workspace> \
```

## 3. Number formatting (host test)

`format_fixed()` (`Core/Src/fixed_point.cpp`, replaces the legacy `floatToStr()`) compiled with the
host's g++ and checked against 13 cases. Negative values are correct (`-0.5` -> `-0.50`,
`-12.345` -> `-12.35`, `-273.15` -> `-273.150` with 3 places); values that round to zero print `0.00`;
NaN -> `nan`; 1e6 -> `ovf`; too small a buffer -> empty string, return 0. One expectation of the test
itself was wrong (`-0.005f` is stored as -0.00499999..., so `0.00` is the correct result).
The test program is not part of the repository.

## 4. On the board

```bash
tools/flash_and_capture.sh Debug/DISCO_L475VG_IOT01A_Thingspeak.elf 60 docs/results/2026-11-12_phase1_console.txt
```

Full output, with the header the script writes: `2026-11-12_phase1_console.txt`. Console part:

```
DISCO_L475VG_IOT01A_Thingspeak -- phase 1: Sensors + Console
CSP4CMSIS 3.1.0, FreeRTOS V10.3.1 (CMSIS-RTOS2), SYSCLK 80 MHz
[    0.008 s] #1  T = 13.87 C  RH = 83.56 %  p = 976.17 hPa
[    5.018 s] #2  T = 13.82 C  RH = 83.45 %  p = 976.11 hPa
[   10.023 s] #3  T = 13.85 C  RH = 83.49 %  p = 976.15 hPa
...
[   55.068 s] #12  T = 13.98 C  RH = 83.26 %  p = 976.23 hPa
```

Observations:

- **12 samples in 60 s, all valid**, numbered 1..12 without gaps: no I2C error, no sample overwritten
  before the Console printed it.
- **Period: 5.005 s** (5.010 s for the first, which includes the sensors' initialisation). The
  timeout guard is relative (`sensors_process.cpp`): each period is 5 s plus the time a reading takes
  (about a dozen I2C register transfers at 100 kHz) plus rounding to whole ticks. Over 60 s the
  samples drift by 60 ms against wall-clock time; harmless here, and ThingSpeak's rate limit (phase 2)
  is a minimum interval, which a slightly longer period never violates.
- **Values:** 13.8–14.0 °C, 83.3–83.6 % RH, 976.1–976.3 hPa, stable from sample to sample. They were
  not compared with a reference instrument.
- **No dynamic allocation:** read over SWD after the 60 s, program running:
  `__sbrk_heap_end = 0x00000000` (newlib's `malloc()` never called) and
  `xMinimumEverFreeBytesRemaining = 0x00000000` (FreeRTOS heap_4 never initialised, i.e. nothing ever
  allocated from it).
- A first run of the same firmware (10:55 UTC, before a parsing fix in the script's heap check)
  printed the same pattern: 12 valid samples, period 5.005 s.
